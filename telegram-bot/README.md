# Telegram-бот «Первые 100 дней»

Регистрация участников и работодателей, заявки на сопровождение и отклики на проверенные вакансии. Каждый вопрос приходит отдельным сообщением с кнопками. Перед отправкой пользователь проверяет ответы. Назад можно вернуться на каждом шаге, незаконченная анкета сохраняется после перезапуска.

Бот работает отдельным процессом на Python 3.11+. Данные хранятся в SQLite. Используется стандартная библиотека Python, установка пакетов не нужна. Веб-приложение React и Spring Boot находится в соседних папках репозитория.

## Запуск из исходников

Откройте терминал в этой папке. Скопируйте пример конфигурации один раз.

```powershell
Copy-Item .env.example .env
```

В `.env` задайте `TELEGRAM_BOT_TOKEN`, полученный от [@BotFather](https://t.me/BotFather), и `TELEGRAM_ADMIN_IDS`. Последняя переменная содержит числовые ID координаторов через запятую. Если ID неизвестен, его можно узнать через [@userinfobot](https://t.me/userinfobot). После настройки сам бот тоже показывает ID командой `/id`.

`PROGRAM_OPERATOR` - название команды или организации, которое увидит человек перед регистрацией. `BOT_DATABASE` позволяет выбрать другое место для базы. Относительный путь считается от папки бота.

Проверьте токен и запустите бота.

```powershell
python main.py --check
python main.py
```

Участники и каждый координатор должны открыть бота в Telegram и нажать «Начать». Telegram разрешает боту первым написать человеку только после того, как человек начал диалог. Остановка через Ctrl+C завершает текущую обработку. Следующий запуск продолжит работу с сохранёнными данными.

Если у этого токена уже есть webhook, приложение сообщит об этом и остановится. Проверка не отключает чужой webhook. Для long polling нужен отдельный бот или явно отключённый прежний webhook.

## Участник

1. Нажимает «Я участник · Регистрация» и читает описание использования данных.
2. Указывает имя, возрастную группу, город и ближайшую цель. Можно указать только имя. Полная дата рождения, адрес, паспорт и СНИЛС не запрашиваются.
3. Проверяет ответы и сохраняет анкету.
4. Нажимает «Нужна помощь», выбирает тему, пишет сообщение и подтверждает отправку. В темах есть участие в программе, первая работа, резюме, бюджет и другой вопрос.
5. Получает номер заявки. Статус и ответ координатора доступны в «Моих заявках».
6. Может посмотреть подходящие по возрасту вакансии и отправить отклик. Перед отправкой перечислены сведения, которые увидит работодатель. Активную заявку можно отозвать после подтверждения.

Участники младше 14 лет могут зарегистрироваться и попросить помощь. Вакансии для них не выводятся. Возрастной фильтр определяет показ предложений, условия реального трудоустройства отдельно проверяет координатор.

## Работодатель

1. Выбирает роль работодателя, указывает организацию, имя представителя и город.
2. Получает решение координатора в Telegram. Координатор может запросить уточнение с объяснением.
3. После подтверждения организации заполняет вакансию. Обязательны должность, город, график, условия оплаты, минимальная возрастная группа, задачи и оформление.
4. После проверки вакансия появляется в списке участников.
5. В «Моих вакансиях» видит отклики, может пригласить кандидата или завершить рассмотрение. Участник и координатор получают уведомления. Координатор помогает согласовать встречу.
6. Может закрыть вакансию. Новые отклики на закрытую вакансию не принимаются, прежние доступны в её карточке.

У одного пользователя могут быть анкета участника и организация. Смена роли не удаляет их. Анкета участника редактируется через «Моя анкета». Для изменения подтверждённых данных организации представитель отправляет обращение координатору.

## Координатор

Команда `/admin` открывает кабинет. Доступ определяется числовыми ID из конфигурации. Проверки прав выполняются для каждого действия независимо от того, какую кнопку прислал клиент Telegram.

В кабинете доступны организации на проверке, вакансии и активные заявки. Координатор подтверждает организацию, публикует или отклоняет вакансию, берёт заявку в работу, отвечает участнику и завершает обращение. Для отклонения нужно написать причину. Приглашение от работодателя отображается отдельным статусом. Счётчик недоставленных сообщений и кнопка повторной доставки помогают обнаружить заблокированные диалоги и восстановить уведомления.

Перед подтверждением работодателя координатор проверяет сведения об организации. Перед публикацией вакансии он проверяет задачи, график, оплату и оформление, в том числе применимость условий для заявленной возрастной группы. Заявка на участие ещё не означает зачисление в группу, это явно указано в описании программы.

## Сценарий демонстрации

Для демонстрации удобно использовать три Telegram-аккаунта. Один указан в `TELEGRAM_ADMIN_IDS`, второй регистрируется работодателем, третий участником.

1. Зарегистрируйте организацию и подтвердите её из кабинета координатора.
2. Работодатель предлагает вакансию помощника в книжном магазине. Координатор проверяет её и публикует.
3. Участник регистрируется, открывает вакансию и пишет отклик. На последнем шаге видит, какие данные будут переданы.
4. Работодатель получает уведомление, открывает отклик и нажимает «Пригласить».
5. Участник видит приглашение. Координатор открывает заявку и отвечает, чтобы согласовать следующий шаг.
6. Отдельно покажите заявку на участие в программе и изменение её статуса на «В работе».

Если аккаунт один, роли можно переключать через меню. На собственную вакансию откликнуться нельзя, для проверки этого этапа нужен второй аккаунт.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Проверяются полные сценарии регистрации и отклика, доступ к чужим заявкам, права координатора, сохранение черновиков, повторы обновлений Telegram, двойные нажатия, старые кнопки, возрастной фильтр, закрытие вакансии во время заполнения отклика, пагинация, экранирование текста и повторная доставка сообщений.

## Постоянная работа на сервере

Из этой папки на сервере с Docker Compose выполните следующие команды после заполнения `.env`.

```sh
docker compose up -d --build
docker compose logs -f bot
```

SQLite и незаконченные формы хранятся в именованном томе `bot-data`, который сохраняется при пересборке контейнера. Токен передаётся через `.env` и не включается в образ. Один токен должен обслуживаться одним процессом long polling. Блокировка файла исключает запуск двух процессов с общей базой, Telegram дополнительно сообщает о конфликте polling для одного токена.

Боту нужен постоянно работающий процесс и постоянный диск. Веб-сайт может размещаться отдельно. Локальный `python main.py` принимает сообщения, пока включён компьютер и работает этот процесс.

Для резервной копии остановите бота и сохраните папку `data` или том `bot-data`. Ещё один вариант - SQLite Backup API, который делает согласованную копию при работающем процессе. Доступ к резервной копии должен быть у ответственной команды.

## Хранение и доставка

Одно обновление Telegram, изменение заявки и уведомления записываются одной транзакцией. Повтор того же обновления не создаёт ещё одну заявку. Повторное нажатие на подтверждение также не создаёт дубликат. У откликов дополнительно есть уникальность пары «участник - вакансия».

Доставка работает через очередь `outbox`. При временной ошибке запрос повторяется с задержкой, при ограничении Telegram учитывается `retry_after`. Недоступный диалог не останавливает доставку другим пользователям. Если процесс завершится между фактической отправкой сообщения и фиксацией успешной доставки, уведомление может повториться. Сама заявка останется одной.

Тексты, токен и полные адреса запросов Telegram в логи не записываются. Файлы `.env`, SQLite, WAL и служебные файлы базы исключены из Git. Перед использованием с реальной группой ответственная организация задаёт правила хранения, исправления и удаления данных, согласовывает информирование участников и назначает координаторов. Встроенный текст `/privacy` описывает фактическое поведение приложения.

## Исходники

| Файл | Назначение |
| --- | --- |
| `main.py` | Запуск, long polling, команды Telegram и остановка |
| `service.py` | Диалоги, роли, заявки, вакансии и модерация |
| `store.py` | SQLite, транзакции, обработанные обновления и очередь |
| `telegram.py` | HTTPS-запросы Bot API, доставка и повторы |
| `config.py` | Настройки из окружения и локального `.env` |
| `tests/test_bot.py` | Проверки сценариев и отказов |

Реализация использует [Telegram Bot API](https://core.telegram.org/bots/api) и [inline-кнопки Telegram](https://core.telegram.org/bots/features#inline-keyboards).
